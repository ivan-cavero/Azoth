## Dead / closed (do not waste time again)

| Lever | Why not |
| --- | --- |
| **`patch-context-gate.py`'s `31DB90` (force the predicate flag to 0)** | **INVERTED.** `31 DB 90` = `xor ebx, ebx` sets the 7th argument of `ClientContext::Initialize` to 0, which is exactly the value that makes `Initialize` run `call 0x1416835B0` (the `Cleanup()` path) on the context it was just handed. That is why the archived script's own header admits "forcing the predicate did not stop the cleanup" — it was forcing the wrong value. Use `scripts/patch-predicate-flag.py` (`mov bl,1` + NOP the `jne`) instead. |
| **Reliable `0x15d` heartbeat** | Sent with flags `0x21` it enters `sent_reliable` and is retransmitted until acked. At ~1/s of unacked datagrams the table grew without bound, `maybe_resend` starved the UDP loop and new DTLS handshakes failed with `@mm_csdkerr_connection_failed` (2026-09-27 02:34). Use flags `0x20` (unreliable). |
| **Privacy-settings mock as the route to `IsMasterPlayer`** | Built and correct (`services/gateway/src/azoth_gateway/routes/privacy.py`, answers 200 through Caddy), but the client **never requests it**: 0 hits in `traffic.jsonl` across three full world attempts, and Frida hooks on the whole static chain (`FUN_14160a1f0` ← `FUN_141688770` ← `0x143edff00` ← `0x143ef4f80`) recorded 0 hits. The `omni.privacy-settings.*` keys were added to the channel (top-level and per region) and the client still never calls it. Keep the route (harmless) but do not chase it as the `+0xa2` trigger. |
| **Hooking `0x14160a754` (the `mov [rax+0xa2], bl` instruction)** | Frida fails with an access violation: the page is protected (EAC hooks per page, not only the `LoadContextAndLevel` prologue). Hooking the containing function works but that function never runs. |
| **Byte-scanning for writers of `[x+0xa2]`** | Only two `mov [reg+0xa2], reg8` exist in all of `.text`; `0x14160a754` is inside the privacy client (never reached) and `0x14251774c` is a false positive (a struct-array fill whose real offset is `rcx+0x51+0x60k-0x5e`, never `+0xa2`). The `+0xa2` write on the real object is indirect (pointer/vtable) or comes from an initializer. Use a hardware watchpoint on the live object, not a byte scan. |
