# 1.460 frontier, then the schema-driven inventory

Feature: make the whole repository describe one client build (1.460), remove the
1.400 layer from the live tree, and turn the field-level knowledge from prose
into a machine-readable schema that a Rust code generator can consume.

Client build this feature targets: **1.460.6033.6024067**, SHA-256
`30fe6461f929ba44178376a72f0765dc5da28ccba20e5006a60a229babd74033`.
The retired build is **1.400.6031.6004151**, SHA-256 `8654f01d…c8e`.

## Log

- **L1** — the user's first request, verbatim: "Trae todos los cambios y analiza
  todo el proyecto y el estado del proyecto en que punto estamos siento que las
  ultimas semanas no avanzamos mucho"
- **L2** — S1, verbatim above. Decision: the stale set is prose, not data. Five of
  the big JSON inventories reproduced on 1.460 under each tool's `--check`; only
  `aoi-trait-registry.json` and `rtti-classes.json` were truly stale. Nothing was
  deleted; the 1.400 prose was archived.
- **L3** — correction found while scanning: the first scan only covered
  `.py/.ts/.js/.astro/.sh` and missed every `.md` reference. A worker caught 8 live
  dangling links. A grep by extension is not a build audit.
- **L4** — correction found while building the gate: `--check` on
  `scan-trait-registry.py` validates an invariant but does not regenerate, so it
  cannot detect a stale artifact. The authoritative signal is the artifact's own
  declared build field.
- **L5** — defect found while regenerating: `rtti.py` hardcoded
  `exe_sha256_prefix: "8654f01d324636d9"`. Fixed to measure the exe it read; option
  A chosen over shipping a permanently-failing audit.
- **L6** — defect found while inspecting the migrated cards: `msg.update` modelled
  `length` and `blob` as two fields, but `prefixed_bytes` already contains its
  length; and the record envelope (4 opaque fields) is framing owned by
  `javelin/frame.py`, not a per-message field.
- **L7** — root cause of "no fixtures": `export-wire-fixtures.py` gated its whole
  run on `server/Cargo.toml` and wrote inside the deleted crate. 400 datagrams;
  round-trip byte-exact for 52/52 uncompressed datagrams and 53/53 state bundles;
  348 LZ4 datagrams cannot be re-encoded in Python and the test says so.
- **L8** — S3 and S4, verbatim above. Work stays on `refactor/knowledge-os`.
- **L9** — the generator is honest, not flattering: it emitted **1** card, refused
  **9** with a stated reason, and reported 21 field-less. The one ready card had no
  real body fixture, so it stayed un-falsified rather than given a synthetic one.
- **L10** — seeding reached 7/15 codegen-ready. `0x5de` is `measured` in the atlas
  but **no byte fixture exists** (its live log is gone), so it is typed but
  unverified. The atlas names **three** Contracts sub-codecs, not two; all three
  are `partial` and have no bytes, so they stay unverified.
- **L11** — the entry path was the crate's first job and two of its three bodies
  were refused. Both causes were mechanical: `level_bounds` needed a literal-count
  array, and the `0x3` card modelled the client request instead of the server
  response. Fixed; `0x3`, `0x663` and `0x65c` now round-trip their real corpus
  bodies, and the body lengths close against the envelope (85+3=88, 106+4=110).
- **L12** — owner decision, verbatim choice: "Todavía no: consolidar y cerrar".
  The crate is deliberately not created this session. Nine cards are codegen-ready
  with no crate consuming them yet; that is the accepted cost.
- **L13** — disclosures: a worker wrote `/tmp/wb-test.json` once, outside the repo,
  and self-reported it; no tracked file was affected. The first commit attempt
  failed because two `git` commands were run in parallel on one repo.
